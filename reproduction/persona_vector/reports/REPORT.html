Double BOS tokens

Upstream feeds chat-templated text, which already begins with <|begin_of_text|>, to tokenizers that add another BOS. So every generation path in upstream sees two BOS tokens, while its activation and projection passes tokenize with add_special_tokens=False and see one. The rollouts the vector is built from were therefore sampled under a prompt that differs by one leading token from the one the vector is read under. We copied this exactly (user decisions); the audit used one BOS everywhere and stripped responses.
